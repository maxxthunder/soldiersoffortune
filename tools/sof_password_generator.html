How the password is built

Each character is a 5-bit number. SNES: alphabet BCDFGHJKLMNPQRSTVWXYZ0123456789@, every number XORed with 21, code in bank $CD (encode $CD3199, decode $CD3039). Genesis: the same alphabet but # in place of @. Each number is XORed with a running sum of the ones before it, characters 1 and 6 swap places, and the checksum is a 4-bit add-and-rotate (encode $733A, decode $7548). Both versions store the same fields, listed here in SNES order:

CharHolds
1Player count, world, 1 checksum bit
2Character pair (30 combinations of two different mercenaries)
3–4P1 / P2 lives
5–6P1 × 11 + P2 level (0–10 each), 3 checksum bits
7–9, 10–12P1 / P2 money, bits 15–1

The SNES checksum is (sum of the 12 numbers − 66) mod 16. Money in the password is cash plus the value of your gear. On load the game subtracts the value of the gear you start with, so your spendable cash ends up a little lower than the figure here. "Lives" and "level" are names inferred from the code: lives start at 3 on a new game, and level goes up through the worlds.
