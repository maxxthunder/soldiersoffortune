# Soldiers of Fortune (USA) â€” reverse engineering

Soldiers of Fortune is the US release of The Bitmap Brothers' *The Chaos Engine*. This repo
holds disassemblies of the SNES and Genesis versions and tools for their password systems. The password
tools also handle the Genesis version, whose passwords store the same data but use a
different encoding.

## Layout

| Path | Contents |
|------|----------|
| `disasm/` | 65816 listings of the SNES ROM, one file per 64 KB bank (`bank_C0.asm` â€¦ `bank_D7.asm`), generated by `tools/disasm.py` |
| `disasm_genesis/` | 68000 listings of the Genesis ROM, one file per 64 KB (`rom_00.asm` … `rom_17.asm`), generated by `tools/disasm68k.py` |
| `docs/sof_password.md` | Password format for both versions: routine addresses, bit layout, checksums |
| `tools/disasm.py` | Disassembler: traces code from the reset/interrupt vectors, tracking register widths across calls and following jump tables |
| `tools/reasm.py` | Reassembles `disasm/` and checks the result is byte-identical to the ROM |
| `tools/disasm68k.py` | Genesis disassembler: traces code from the vector table, then from pointers it can vet (long and word-offset jump tables, `MOVE.L #addr`, code after an `RTS`) |
| `tools/reasm68k.py` | Reassembles `disasm_genesis/` and checks the result is byte-identical to the ROM |
| `tools/check_68k.py` | Round-trips every 68000 opcode word through the disassembler and reassembler |
| `tools/sof_password.py` | Password decoder/encoder for SNES and Genesis |
| `tools/sof_password_generator.html` | The same in a web page: build a password for any party, or decode one |
| `tools/check_generator.py` | Checks the web page's JavaScript against `sof_password.py` |
| `tools/sof_genesis_romcheck.py` | Checks `sof_password.py` against the Genesis ROM's own password code, run in an emulator |

## You need

- **The ROMs, which are not included.** Put them in the repo root as
  `Soldiers of Fortune (USA).sfc` (SNES) and `Soldiers of Fortune (USA).md` (Genesis).
  `.gitignore` keeps them out of commits.
- Python 3.8 or newer.
- Optional: Node.js for `check_generator.py`, and `pip install unicorn` for `sof_genesis_romcheck.py`.

## Usage

Decode passwords (with no arguments, it runs its self-test):

```bash
python tools/sof_password.py W1V19S2SH21Q
python tools/sof_password.py --genesis 9NB5JM115GQ#
```

To make a password, open `tools/sof_password_generator.html` in a browser.
It works offline.

Regenerate the disassembly and confirm it rebuilds the exact ROM:

```bash
python tools/disasm.py "Soldiers of Fortune (USA).sfc" disasm
python tools/reasm.py disasm "Soldiers of Fortune (USA).sfc"
python tools/disasm68k.py "Soldiers of Fortune (USA).md" disasm_genesis
python tools/reasm68k.py disasm_genesis "Soldiers of Fortune (USA).md"
```

Run the cross-checks:

```bash
python tools/check_generator.py
python tools/sof_genesis_romcheck.py
python tools/check_68k.py
```

## Reading the listings

Each instruction line shows its address, its raw bytes and the register widths in effect:
`m`/`x` mean 8-bit A/index registers, and `M`/`X` mean 16-bit. Bytes the tracer never
reached are shown as `db` and may be code or data. Only about 3% of the ROM is traced as
code so far. The rest is mostly graphics and data, plus code reached only through RAM
vectors or other indirect jumps. To trace more of it, add `(address, m, x)` to
`EXTRA_ENTRIES` in `tools/disasm.py`.

Genesis lines show the address and the raw words. Unreached bytes are `dc.b`. The code sits
in `$000000`–`$01EB2E`, and about 55% of that is traced (4.4% of the ROM); the rest of that range
is mostly tables. Above it the ROM is graphics and level data. The password decoder is at
`L_007548` and the encoder at `$00834A`. Guessed entry points must decode cleanly along every
path and avoid instructions only data turns into (`rare()` in `tools/disasm68k.py`); add
addresses to its `EXTRA_ENTRIES` to trace more.
